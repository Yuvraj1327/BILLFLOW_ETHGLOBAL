## 1. Manual steps YOU must do (nothing here was done for you)
1. Fund the deployer wallet with test WBT (faucet.testnet.whitechain.io).
2. Confirm the USDT address: set `USDT_ADDRESS` in `contracts/.env`, run
   `forge script script/CheckUsdt.s.sol --rpc-url $WHITECHAIN_SEPOLIA_RPC_URL` and compare name/symbol/decimals with Whitechain/sponsor docs. Do not continue if it differs or reverts.
3. Run tests locally: `cd contracts && ./install-deps.sh && forge test` (expect 66 passing; if forge cannot download solc, set `FOUNDRY_SOLC` to a solc 0.8.28 binary).
4. Set the role addresses in `contracts/.env`, import a deployer key into a Foundry keystore (`cast wallet import deployer --interactive`), then
   `forge script script/Deploy.s.sol --rpc-url $WHITECHAIN_SEPOLIA_RPC_URL --account deployer --broadcast`.
5. Record the two addresses in `docs/deployments.md` and in `backend/.env`.
6. Verify both contracts on `explorer.testnet.whitechain.io` (Blockscout). Find the verification API/UI route in Whitechain's docs; with a Blockscout API: `forge verify-contract <addr> src/BillFlowPayments.sol:BillFlowPayments --chain-id 1874 --verifier blockscout --verifier-url <EXPLORER_API_URL>/api --constructor-args $(cast abi-encode "constructor(address,address,address,address)" <usdt> <admin> <signer> <pauser>) --compiler-version 0.8.28`. Constructor for InvoiceFinancing: `(address,address)` = `<usdt> <admin>`. If verification fails, use the explorer's flattened-source form (`forge flatten`), settings: solc 0.8.28, optimizer on / 200 runs, EVM `shanghai`.
7. Obtain test USDT, then perform one real payment and one real financing cycle (section 4) and save the tx hashes.

## 2. Backend responsibilities
**Ids and hashes** (must be reproducible): `invoiceId = keccak256(utf8(invoice.uuid))`; `invoiceHash = keccak256` of the canonical invoice data (define the exact field order/encoding in Step 3 and freeze it); `documentHash = keccak256(pdf bytes)` (or sha256 stored in DB — choose one and keep it consistent); `debtorRef = keccak256(debtor identifier)` (no personal data on-chain).

**Signing a quote** (verified: Python `eth_account` digest equals the contract's `hashQuote`):
```python
from eth_account import Account
from eth_account.messages import encode_typed_data
msg = {
  "types": {"EIP712Domain": [{"name":"name","type":"string"},{"name":"version","type":"string"},
                             {"name":"chainId","type":"uint256"},{"name":"verifyingContract","type":"address"}],
            "Quote": [{"name":"invoiceId","type":"bytes32"},{"name":"invoiceHash","type":"bytes32"},
                      {"name":"merchant","type":"address"},{"name":"payer","type":"address"},
                      {"name":"amount","type":"uint256"},{"name":"invoiceTotal","type":"uint256"},
                      {"name":"nonce","type":"uint256"},{"name":"expiry","type":"uint64"}]},
  "primaryType": "Quote",
  "domain": {"name":"BillFlowPayments","version":"1","chainId":1874,"verifyingContract":PAYMENTS_ADDR},
  "message": {...}}
sig = Account.sign_message(encode_typed_data(full_message=msg), QUOTE_SIGNER_KEY).signature
```
Nonce: random 256-bit per quote, stored in DB until used/expired. Expiry ≤ 15 min. **Never sign a quote for an invoice that is cancelled, already paid, or has a financing row.** If an invoice is cancelled after a quote was issued, call `revokeNonce` (signer key).

**Indexer** (poll `eth_getLogs`, ≥ `min_confirmations`, idempotent on `(tx_hash, log_index)`):
| Event | DB effect |
|---|---|
| `BillFlowPayments.InvoicePaid` | verify `invoiceId`/`merchant`/`invoiceHash` match the invoice, then insert `payments` (CONFIRMED), set `paid_amount_base = totalPaid`, `status = PAID` if `totalPaid == invoiceTotal` else `PARTIALLY_PAID`, `paid_tx_hash` |
| `InvoiceRegistered` / `InvoiceVerified` | store ids; `financing_offers` → UNDER_REVIEW / APPROVED |
| `OfferCreated` | `LISTED`, `onchain_offer_id = invoiceId`, `create_tx_hash` |
| `OfferFunded` | insert/confirm `investments`, `FUNDED`, `funded_at` |
| `OfferRepaid` + `OfferSettled` | investment `SETTLED`, `repayment_*`, financing `SETTLED` |
| `OfferCancelled` / `OfferExpired` / `OfferDefaulted` / `InvoiceRejected` | matching financing status |
| `BusinessApprovalUpdated` / `InvestorApprovalUpdated` | mirror verification state |
The event payload is the source of truth; never trust a client-supplied `tx_hash` beyond fetching its receipt.

**Who holds which role.** `VERIFIER_ROLE` is the human trust decision — recommended: the admin signs `verifyInvoice` / `setBusinessApproved` / `setInvestorApproved` from their own wallet in the admin panel (human-signed). `OPERATOR_ROLE` and `ISSUER_ROLE` may be backend keys. `QUOTE_SIGNER` is a backend key. All testnet-only; rotate after the event.

## 3. Wallet (Flutter Web) flows
- **Pay:** ensure chain 1874 → read `decimals()` / `balanceOf` → `USDT.approve(payments, amount)` → `payments.payInvoice(quote, signature)` → send `tx_hash` to backend → wait for backend status.
- **Fund:** `USDT.approve(financing, advance)` → `financing.fund(invoiceId)`.
- **Repay:** `USDT.approve(financing, faceValue)` → `financing.repay(invoiceId)`.
- Amounts are base units; never hard-code decimals — read them from the token.

## 4. End-to-end acceptance checklist (to run on testnet after deployment)
1. Admin wallet: `setBusinessApproved(merchant)`, `setInvestorApproved(investor)`.
2. Merchant: `registerInvoice` → admin `verifyInvoice(id, ackHash)` → merchant `createOffer(id, advance, deadline)`.
3. Investor: approve + `fund(id)`; confirm business received the advance.
4. Debtor: approve + `repay(id)`; confirm investor received face value, status Settled.
5. Separately, an Operate payment: signed quote → approve → `payInvoice`; confirm merchant balance and `InvoicePaid`.
6. Save every tx hash + explorer link into `docs/deployments.md`. **None of this has been executed yet.**
